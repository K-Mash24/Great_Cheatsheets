## The Two Models

### OSI Model (7 Layers) — The Reference Framework

The **OSI (Open Systems Interconnection)** model is a theoretical framework for understanding network communication. It breaks down data transmission into seven discrete layers, each with a single responsibility.

**Mnemonic (Layer 7 → 1):** All People Seem To Need Data Processing

| Layer | Name | Purpose | PDU |
|-------|------|---------|-----|
| 7 | **Application** | Enables communication between applications (HTTP, HTTPS, FTP, SMTP, SSH) | Data |
| 6 | **Presentation** | Translates data through encryption (TLS/SSL), compression (GZIP), encoding (UTF-8) | Data |
| 5 | **Session** | Establishes, maintains, and terminates communication sessions; TLS handshake occurs here | Data |
| 4 | **Transport** ⭐ | Reliable end-to-end delivery via TCP or fast connectionless delivery via UDP | Segment |
| 3 | **Network** ⭐ | Logical addressing and routing using IP; forwards packets hop-by-hop | Packet |
| 2 | **Data Link** | Reliable delivery between directly connected devices using MAC addresses; Ethernet, Wi-Fi | Frame |
| 1 | **Physical** | Transmits raw bits across physical media (electrical signals, light, radio waves) | Bit |

⭐ = SAA priority layers

### TCP/IP Model (4 Layers) — The Working Reality

The **TCP/IP (Transmission Control Protocol / Internet Protocol)** model is the practical framework that actually runs the internet. It consolidates the OSI model into four layers by merging related concerns.

| TCP/IP Layer | OSI Equivalent | Key Protocols | Purpose |
|--------------|----------------|---------------|---------|
| **4 — Application** | 7, 6, 5 | HTTP, HTTPS, DNS, SMTP, FTP, SSH, TLS | All application-level communication |
| **3 — Transport** | 4 | TCP, UDP | End-to-end delivery between applications |
| **2 — Internet** | 3 | IP, ICMP | Logical addressing and routing |
| **1 — Network Access** | 2, 1 | Ethernet, Wi-Fi, ARP, NICs, cables | Local delivery and physical transmission |

**Why the difference?**
- **OSI** = Reference model for teaching and troubleshooting
- **TCP/IP** = Working model that the internet actually uses
- Transport and Internet layers map exactly 1:1 between models

## Understanding Encapsulation

### Core Concept

**Encapsulation** is the mechanism that makes both models work. Each layer wraps data from the layer above in its own header, adding only the information needed to perform that layer's function. The reverse process on the receiving side is **decapsulation**.

### The Encapsulation Stack (Data Wrapping)

```
SENDER — Encapsulation (Down the Stack)
──────────────────────────────────────────────────
Layer 7  Data              HTTP request created by browser
         ↓
Layer 4  Segment           [TCP header: ports, seq#] + Data
         ↓
Layer 3  Packet            [IP header: src IP, dst IP] + Segment
         ↓
Layer 2  Frame             [MAC header: src MAC, dst MAC] + Packet + [FCS]
         ↓
Layer 1  Bits              101101000110... transmitted as signal


RECEIVER — Decapsulation (Up the Stack)
──────────────────────────────────────────────────
Layer 1  Bits              Raw signal received, frame reconstructed
         ↓
Layer 2  Frame             MAC header stripped → Packet verified
         ↓
Layer 3  Packet            IP header stripped → Segment verified
         ↓
Layer 4  Segment           TCP header stripped → Data verified
         ↓
Layer 7  Data              Original HTTP request delivered to server
```

### Why Encapsulation Works: Separation of Concerns

Each layer reads **only its own header** and ignores everything else:

- A **router** (Layer 3) reads only the IP header — no knowledge of HTTP
- The **OS** (Layer 4) reads only the TCP header — doesn't care about MAC addresses
- The **web app** (Layer 7) receives only the HTTP request — no knowledge of physical transmission

This independence means any layer can be swapped without affecting others. Replacing Wi-Fi with Ethernet changes only layers 1 & 2 — layers 3, 4, and 7 are completely unaffected.

### PDU Reference

| Layer | PDU Name | What It Contains |
|-------|----------|------------------|
| 7–5 | **Data** | Application, Presentation, Session payload |
| 4 | **Segment** | TCP/UDP header + data (ports, sequence numbers) |
| 3 | **Packet** | IP header + segment (source/destination IPs) |
| 2 | **Frame** | MAC header + packet + FCS (source/destination MACs) |
| 1 | **Bit** | Raw signal (electrical, optical, or radio waves) |

**FCS (Frame Check Sequence)** — A checksum trailer (not header) at Layer 2. Receiver recalculates it; if mismatched, the frame was corrupted and is discarded.

### Encapsulation Analogy

Think of nested gift boxes:

- **The gift** = Data (HTTP request)
- **Innermost box label** = TCP header (port number — which app gets it?)
- **Shipping box label** = IP header (destination IP — which machine?)
- **Courier bag label** = MAC header (next hop only — which local device?)
- **Courier van** = Layer 1 (physical medium carrying everything)

Each handler reads only their label and passes it on. Decapsulation is opening each box in reverse order until the original gift is revealed.

## Layer-by-Layer Breakdown

### Layer 7 — Application

**Function:** Enable communication between applications and the network.

**What happens here:**
- End user directly interacts with this layer
- Protocol handling: HTTP/HTTPS (web), FTP (file transfer), SMTP (email), SSH (remote access), DNS (name resolution)
- Examples: Web browsers, email clients, SSH terminals

**Key protocols:**
- HTTP (port 80) — Unencrypted web traffic
- HTTPS (port 443) — Encrypted web traffic with TLS
- SMTP (port 25) — Email sending
- POP3 (port 110) — Email download
- IMAP (port 143) — Email sync and store
- FTP (ports 20, 21) — File transfer
- SSH (port 22) — Secure remote access
- DNS (port 53) — Name resolution

---

### Layer 6 — Presentation

**Function:** Translate data between application and network formats.

**What happens here:**
- **Encryption:** TLS/SSL encrypts HTTPS requests so interceptors can't read content
- **Compression:** GZIP reduces data size for faster transmission
- **Encoding:** UTF-8, ASCII ensure both sides agree on character representation

**Key point:** TLS/SSL ensures both sides understand the format before data is exchanged.

---

### Layer 5 — Session

**Function:** Establish, maintain, and terminate communication sessions.

**What happens here:**
- Manages conversation lifecycle (e.g., keeping login sessions alive across multiple requests)
- **TLS handshake occurs here** — verifies server identity and negotiates encryption key before data exchange
- Prevents data from different conversations mixing

**Key point:** Session layer manages when conversations start and stop.

---

### Layer 4 — Transport ⭐ (SAA Priority)

**Function:** Provide reliable, end-to-end delivery of data between applications.

**What happens here:**
- Breaks data into segments and assigns sequence numbers
- Assigns **port numbers** to identify target applications
- Guarantees delivery and ordering (TCP) OR provides fast connectionless delivery (UDP)

**TCP (Transmission Control Protocol):**
- Reliable — segments are numbered and re-requested if lost
- Ordered — data arrives in correct sequence
- Connection-oriented — establishes connection before sending
- Slower but guaranteed
- Used for HTTP, HTTPS, SMTP, SSH, FTP

**UDP (User Datagram Protocol):**
- Fast — sends data without guarantees
- Connectionless — no setup required
- Lower overhead
- Used for DNS queries, VoIP, online gaming, video streaming

**Port numbers:**
- Well-known ports (0–1023): HTTP (80), HTTPS (443), SSH (22), DNS (53)
- Registered ports (1024–49151): Specific applications
- Ephemeral ports (49152–65535): Temporary OS assignments

**PDU:** Segment (contains TCP/UDP header + data)

---

### Layer 3 — Network ⭐ (SAA Priority)

**Function:** Handle logical addressing and routing across multiple networks.

**What happens here:**
- Uses **IP addresses** to identify source and destination machines
- Forwards packets hop-by-hop toward destination via routers
- **IP (Internet Protocol)** wraps each TCP segment in a packet with source and destination IPs
- **ICMP (Internet Control Message Protocol)** provides diagnostic functions (ping, traceroute)

**How it works:**
- Router reads IP header to determine next hop
- Each router forwards one step closer to destination
- No single router needs to know the entire path

**PDU:** Packet (IP header + segment)

**Key protocols:**
- IP (IPv4, IPv6)
- ICMP (ping, traceroute)
- OSPF, BGP (routing protocols)

---

### Layer 2 — Data Link

**Function:** Transfer data reliably between directly connected devices on same network segment.

**What happens here:**
- Uses **MAC addresses** to identify hardware devices
- Manages access to physical medium (Ethernet, Wi-Fi)
- **ARP (Address Resolution Protocol)** discovers MAC addresses when only IP is known
- **FCS (Frame Check Sequence)** detects corrupted frames

**Device behavior:**
- **Switches** operate at this layer — forward frames based on MAC addresses
- **Routers** operate at layer 3 — forward packets based on IP addresses

**PDU:** Frame (MAC header + packet + FCS trailer)

**Key protocols:**
- Ethernet
- Wi-Fi (802.11)
- ARP (Address Resolution Protocol)

---

### Layer 1 — Physical

**Function:** Transmit raw bits across physical medium.

**What happens here:**
- Converts frames into signals:
  - Electrical signals (copper cable)
  - Light pulses (fiber optic)
  - Radio waves (Wi-Fi)
- Governs voltage levels, frequencies, connector types
- No traditional "protocols" operate here

**Hardware examples:**
- Network interface cards (NICs)
- Ethernet cables (twisted pair, coaxial)
- Fiber optic cables
- Wireless antennas

**PDU:** Bit (raw 0s and 1s as signals)

## Protocols and Ports

### Port Numbering Ranges

| Range | Name | Purpose | Examples |
|-------|------|---------|----------|
| 0–1023 | **Well-known** | Standard protocols | HTTP (80), HTTPS (443), SSH (22), DNS (53) |
| 1024–49151 | **Registered** | Specific applications | MySQL (3306), PostgreSQL (5432) |
| 49152–65535 | **Ephemeral** | Temporary OS assignments | Dynamic client ports |

### Web Protocols

| Port | Protocol | Transport | Purpose |
|------|----------|-----------|---------|
| 80 | HTTP | TCP | Unencrypted web traffic |
| 443 | HTTPS | TCP | Web traffic encrypted with TLS (**default for modern browsing**) |
| 8080 | HTTP alt | TCP | Alternative HTTP port (development, proxies) |

---

### Email Protocols

| Port | Protocol | Transport | Purpose |
|------|----------|-----------|---------|
| 25 | SMTP | TCP | Sends email between mail servers |
| 110 | POP3 | TCP | Downloads email to local client, typically deletes from server |
| 143 | IMAP | TCP | Reads email from server while keeping it stored there |
| 465 | SMTPS | TCP | SMTP over TLS — encrypted email submission |

**Email logic:**
- **SMTP / SMTPS** = Outbound sending
- **POP3** = Download and remove from server
- **IMAP** = Read while leaving on server (**most modern clients use this**)

---

### Infrastructure Protocols

| Port | Protocol | Transport | Purpose |
|------|----------|-----------|---------|
| 53 | DNS | TCP + UDP | Resolves hostnames to IP addresses (UDP for standard, TCP for large responses) |
| 67 | DHCP (server) | UDP | Assigns IP addresses to devices joining network |
| 68 | DHCP (client) | UDP | Receives IP address assignment |
| 3306 | MySQL | TCP | MySQL/MariaDB database connections |
| 5432 | PostgreSQL | TCP | PostgreSQL database connections |

**Why DHCP uses UDP:** The client doesn't yet have an IP address when making its first request, so TCP (which requires established connection) cannot be used.

---

### File Transfer Protocols

| Port | Protocol | Transport | Purpose |
|------|----------|-----------|---------|
| 20 | FTP data | TCP | Carries actual file data in active FTP |
| 21 | FTP | TCP | Control channel (login, commands) |

**Key point:** FTP uses **two ports** — 21 for control conversation and 20 for data transfer. Both must be open.

---

### Security & Remote Access

| Port | Protocol | Transport | Purpose |
|------|----------|-----------|---------|
| 22 | SSH | TCP | **Encrypted** remote login and command execution |
| 23 | Telnet | TCP | **Unencrypted** remote login (**insecure — replace with SSH**) |
| 3389 | RDP | TCP | Remote Desktop Protocol — graphical access to Windows machines |

**SSH vs Telnet:** Both provide remote access, but Telnet sends everything in plain text. SSH encrypts the session. Telnet should never be used in production.

## Key Concepts & Memory Aids

### Understanding "How Data Travels"

1. **Application creates data** (Layer 7) — HTTP request in browser
2. **Transport adds connection info** (Layer 4) — Which port? TCP or UDP?
3. **Network adds routing info** (Layer 3) — Which destination IP?
4. **Data Link adds local delivery** (Layer 2) — Which MAC address next?
5. **Physical transmits the signal** (Layer 1) — Electrical, optical, or radio

### IP Address vs Port Number

- **IP Address** = Building's street address (gets data to correct machine)
- **Port Number** = Flat number inside building (gets data to correct application)

Both needed to reach correct destination.

### TCP vs UDP

| Aspect | TCP | UDP |
|--------|-----|-----|
| Reliability | Guaranteed delivery | No guarantees |
| Ordering | Ordered arrival | May arrive out of order |
| Connection | Established connection | Connectionless |
| Speed | Slower (acknowledgments) | Faster (no overhead) |
| Use cases | HTTP, SMTP, SSH, FTP | DNS, VoIP, gaming, video |

### MAC Address vs IP Address

- **MAC address** (Layer 2) — Identifies device on same network segment (Ethernet/Wi-Fi)
- **IP address** (Layer 3) — Identifies device across internet

A packet can be routed across the world (IP changes at each hop), but the MAC address only matters locally.

### Routers vs Switches

- **Router** (Layer 3) — Routes packets between networks based on IP addresses
- **Switch** (Layer 2) — Forwards frames within same network based on MAC addresses

### HTTPS Security

- **HTTP** (port 80) = Unencrypted text visible to anyone snooping
- **HTTPS** (port 443) = HTTP encrypted with TLS
- **TLS handshake** (Layer 5) = Verifies server identity and negotiates encryption key
- Result = Website traffic is encrypted end-to-end

### The OSI/TCP/IP Divide

- **Use OSI model** when: Teaching, troubleshooting, or explaining concepts
- **Use TCP/IP model** when: Discussing actual internet operation, practical implementation
- **Both are correct** — they're just different abstraction levels

### Common Exam Traps

- **Telnet (23) vs SSH (22)** — Telnet is unencrypted; SSH is encrypted. Always use SSH.
- **POP3 vs IMAP** — POP3 removes email from server; IMAP keeps it. IMAP is modern standard.
- **HTTP vs HTTPS** — Always prefer HTTPS (encrypted)
- **TCP vs UDP** — TCP is reliable but slower; UDP is faster but unreliable. Choose based on requirements.
- **FTP uses two ports** — 21 (control) + 20 (data). Both must be open.
- **DNS uses both TCP and UDP** — UDP for standard queries, TCP for large responses.

### Encapsulation in Plain English

Data travels down the stack, getting wrapped at each layer:
1. Application wraps it in application protocol (HTTP)
2. Transport wraps it in TCP/UDP (adds port)
3. Network wraps it in IP (adds IP address)
4. Data Link wraps it in Ethernet (adds MAC address)
5. Physical sends it as bits

Receiver reverses the process, unwrapping at each layer until original data is intact. Each layer only cares about its own wrapper.

## Real-World Example: HTTPS Request

### Scenario
You type `https://example.com` in your browser.

### What happens at each layer:

**Layer 7 (Application):** Browser creates HTTP GET request
```
GET / HTTP/1.1
Host: example.com
```

**Layer 6 (Presentation):** TLS encryption kicks in (layer 5 TLS handshake already completed)
```
Encrypted HTTP request
```

**Layer 4 (Transport):** OS wraps in TCP segment with source port (ephemeral) and destination port 443
```
[TCP: src_port=52891, dst_port=443, seq=1000] + Encrypted HTTP
```

**Layer 3 (Network):** IP layer wraps with source IP and destination IP
```
[IP: src=192.168.1.100, dst=93.184.216.34] + [TCP: ...] + Encrypted HTTP
```

**Layer 2 (Data Link):** Ethernet wraps with local MAC addresses (next hop)
```
[MAC: src=AA:BB:CC:DD:EE:FF, dst=00:11:22:33:44:55] + [IP: ...] + ... + [FCS]
```

**Layer 1 (Physical):** Converted to electrical signals and sent over cable

### On the server side, the process reverses (decapsulation):
1. Physical layer receives signals
2. Data Link layer strips MAC header, verifies FCS
3. Network layer strips IP header
4. Transport layer strips TCP header, confirms sequence
5. Application layer receives original HTTPS request

## Study Tips for SAA Certification

1. **Know the OSI model mnemonic:** "All People Seem To Need Data Processing"
2. **Focus on Layers 3 & 4:** Routers (Layer 3) and TCP/UDP (Layer 4) are exam priorities
3. **Memorize port numbers:** Especially 80, 443, 22, 53, 3306, 3389
4. **Understand encapsulation:** It's the foundation of everything
5. **TCP vs UDP:** Know when to use each
6. **SSH vs Telnet:** SSH is always the secure choice
7. **HTTP vs HTTPS:** HTTPS is encrypted, HTTP is not
8. **Routers vs Switches:** Different layers, different jobs
