# Protocols and common port numbers

---

## Core definitions

### 👉 Protocol

An agreed set of rules that two machines follow so they can understand each
other. Without a shared protocol, communication between devices is meaningless
noise. HTTP, for example, defines exactly how a browser requests a web page and
how a server responds — both sides must follow the same rules for the exchange
to work.

---

### 👉 Port number

An IP address gets data to the right machine. A port number gets it to the
right application on that machine. Think of the IP address as a building's
street address and the port number as the flat number inside — both are needed
to reach the correct destination.

Port numbers run from 0 to 65535 and are divided into three ranges:

| Range         | Name             | Purpose                                              |
|---------------|------------------|------------------------------------------------------|
| 0 – 1023      | Well-known ports | Reserved for standard protocols (HTTP, SSH, DNS etc) |
| 1024 – 49151  | Registered ports | Used by specific applications (databases etc)        |
| 49152 – 65535 | Ephemeral ports  | Temporarily assigned by the OS for outgoing connections |

For SAA studies, well-known ports must be known from memory.

## Port numbers by category

### Web

| Port | Protocol  | Transport | What it does                                                        |
|------|-----------|-----------|---------------------------------------------------------------------|
| 80   | HTTP      | TCP       | Hypertext Transfer Protocol — unencrypted web traffic               |
| 443  | HTTPS     | TCP       | HTTP Secure — web traffic encrypted with TLS. Default for all modern browsing |
| 8080 | HTTP alt  | TCP       | Alternative HTTP port — used for development servers or proxies when port 80 is unavailable |

---

### Email

| Port | Protocol | Transport | What it does                                                         |
|------|----------|-----------|----------------------------------------------------------------------|
| 25   | SMTP     | TCP       | Simple Mail Transfer Protocol — sends email between mail servers     |
| 110  | POP3     | TCP       | Post Office Protocol v3 — downloads email to a local client, typically deletes from server after download |
| 143  | IMAP     | TCP       | Internet Message Access Protocol — reads email from a server while keeping it stored there |
| 465  | SMTPS    | TCP       | SMTP over TLS — encrypted email submission from client to mail server |

Email protocol logic:
- SMTP / SMTPS — outbound sending
- POP3 — download and remove from server
- IMAP — read while leaving on server (used by most modern clients)

### Infrastructure

| Port | Protocol | Transport | What it does                                                         |
|------|----------|-----------|----------------------------------------------------------------------|
| 53   | DNS      | TCP + UDP | Domain Name System — resolves hostnames to IP addresses. UDP for standard queries, TCP for large responses |
| 67   | DHCP     | UDP       | Dynamic Host Configuration Protocol (server) — assigns IP addresses to devices joining a network |
| 68   | DHCP     | UDP       | Dynamic Host Configuration Protocol (client) — receives IP address assignment from the server |
| 3306 | MySQL    | TCP       | MySQL and MariaDB database connections                               |
| 5432 | PostgreSQL | TCP     | PostgreSQL database connections                                      |

---

### File transfer

| Port | Protocol | Transport | What it does                                                         |
|------|----------|-----------|----------------------------------------------------------------------|
| 20   | FTP data | TCP       | File Transfer Protocol — carries the actual file data in an active FTP session |
| 21   | FTP      | TCP       | File Transfer Protocol — control channel, manages commands and authentication |

FTP uses two ports: 21 for the control conversation (login, commands) and 20
for the actual data transfer. Both must be open for FTP to function.

---

### Security

| Port | Protocol | Transport | What it does                                                         |
|------|----------|-----------|----------------------------------------------------------------------|
| 22   | SSH      | TCP       | Secure Shell — encrypted remote login and command execution          |
| 23   | Telnet   | TCP       | Unencrypted remote login — insecure, replaced by SSH. Appears in exam questions as the protocol to disable or replace |
| 3389 | RDP      | TCP       | Remote Desktop Protocol — graphical remote access to Windows machines |

## Key distinctions to remember

- **HTTP vs HTTPS** — port 80 is unencrypted, port 443 is encrypted with TLS.
  Always prefer HTTPS.
- **SSH vs Telnet** — both provide remote access, but Telnet (23) sends
  everything in plain text. SSH (22) encrypts the session. Telnet should never
  be used on a production system.
- **POP3 vs IMAP** — POP3 downloads and removes email from the server. IMAP
  keeps email on the server and syncs across devices. Most modern clients use
  IMAP.
- **DNS uses both TCP and UDP** — UDP for standard queries (fast, small), TCP
  when the response is too large for a single UDP packet.
- **FTP uses two ports** — 21 for commands, 20 for data. Both must be open.
- **DHCP uses UDP** — the client does not yet have an IP address when it makes
  its first request, so TCP (which requires an established connection) cannot
  be used.
