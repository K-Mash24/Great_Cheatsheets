# IP Addressing

IP (Internet Protocol) addressing is the system that gives every device on a
network a unique identifier so that data knows where to go. This section covers
IPv4 structure, binary conversion, public and private ranges, special addresses,
and IPv6 fundamentals.

---

## 1. IPv4 address structure

### What an IPv4 address is

A 32-bit numerical label assigned to every device on a network, written as four
decimal numbers separated by dots. Each of those four numbers is called an
**octet** — it represents 8 bits and always has a value between 0 and 255.

```
192      .    168      .    1        .    1
11000000      10101000      00000001      00000001
 octet 1       octet 2       octet 3       octet 4
 (8 bits)      (8 bits)      (8 bits)      (8 bits)
                    total = 32 bits
```

The 0–255 range per octet is not a convention — it is a hard mathematical
limit. 8 bits can represent 2⁸ = 256 values (0 through 255).

---

### Network ID and Host ID

Every IPv4 address is divided into two parts:

**Network ID (network address):** The portion of an IP address that identifies
which network a device belongs to. All devices on the same network share the
same network ID.

**Host ID:** The portion of an IP address that identifies a specific device
within that network. The host ID must be unique within the network.

```
Example: 192.168.1.5

Network ID  →  192.168.1    (identifies the network)
Host ID     →  5            (identifies this specific device)
```

The exact boundary between network ID and host ID is determined by the subnet
mask — covered in depth in section 3 (Subnetting and CIDR).

---

### Network address and broadcast address

Within any network block, two addresses are reserved and cannot be assigned to
a device:

**Network address:** The first address in the block — where the host ID portion
is all zeros. It identifies the network itself.
```
Example: 192.168.1.0  →  network address of the 192.168.1 network
```

**Broadcast address:** The last address in the block — where the host ID
portion is all ones (255 in decimal). A packet sent to this address is
delivered to every device on that network simultaneously.
```
Example: 192.168.1.255  →  broadcast address of the 192.168.1 network
```

This means in any network block, the first and last addresses are always
reserved. A network of 256 addresses (192.168.1.0 – 192.168.1.255) has only
254 usable host addresses (192.168.1.1 – 192.168.1.254).

## 2. Binary and decimal conversion

### The powers of 2 method

Every octet is 8 bits. Each bit position represents a fixed power of 2, always
in this order from left to right:

```
Bit position:   7      6      5      4      3      2      1      0
Power of 2:   128     64     32     16      8      4      2      1
```

A bit is either 1 (that power contributes to the total) or 0 (it does not).
The decimal value of the octet is the sum of all contributing powers.

**Method:** Work left to right through each bit position. Ask "does this power
fit into my remaining value?" If yes — write 1, subtract it. If no — write 0.
Continue until all 8 positions are filled. Verify by summing the 1 positions
back to decimal.

---

### Worked examples

**Converting 192:**

| Position | Power | Fits? | Remainder | Bit |
|----------|-------|-------|-----------|-----|
| 7        | 128   | Yes   | 64        | 1   |
| 6        | 64    | Yes   | 0         | 1   |
| 5        | 32    | No    | 0         | 0   |
| 4        | 16    | No    | 0         | 0   |
| 3        | 8     | No    | 0         | 0   |
| 2        | 4     | No    | 0         | 0   |
| 1        | 2     | No    | 0         | 0   |
| 0        | 1     | No    | 0         | 0   |

Result: **11000000** → 128 + 64 = 192 ✓

---

**Converting 168:**

| Position | Power | Fits? | Remainder | Bit |
|----------|-------|-------|-----------|-----|
| 7        | 128   | Yes   | 40        | 1   |
| 6        | 64    | No    | 40        | 0   |
| 5        | 32    | Yes   | 8         | 1   |
| 4        | 16    | No    | 8         | 0   |
| 3        | 8     | Yes   | 0         | 1   |
| 2        | 4     | No    | 0         | 0   |
| 1        | 2     | No    | 0         | 0   |
| 0        | 1     | No    | 0         | 0   |

Result: **10101000** → 128 + 32 + 8 = 168 ✓

---

**Converting 1:**

| Position | Power | Fits? | Remainder | Bit |
|----------|-------|-------|-----------|-----|
| 7        | 128   | No    | 1         | 0   |
| 6        | 64    | No    | 1         | 0   |
| 5        | 32    | No    | 1         | 0   |
| 4        | 16    | No    | 1         | 0   |
| 3        | 8     | No    | 1         | 0   |
| 2        | 4     | No    | 1         | 0   |
| 1        | 2     | No    | 1         | 0   |
| 0        | 1     | Yes   | 0         | 1   |

Result: **00000001** → 1 ✓

---

### Full address: 192.168.1.1 in binary

```
Decimal:   192        168        1          1
Binary:    11000000   10101000   00000001   00000001

Full 32-bit address:
11000000 . 10101000 . 00000001 . 00000001
```

## 3. Public vs private IP ranges (RFC 1918)

There are only ~4.3 billion possible IPv4 addresses (2³² = 4,294,967,296).
There are far more devices on earth than that. To solve this, certain address
ranges were designated as **private** — reserved for use inside local networks
only, never routable on the public internet.

This was formalised in **RFC 1918** (Request for Comments 1918 — the naming
convention for internet standards documents).

### The three private ranges

| Range                           | CIDR notation    | Addresses     | Common use              |
|---------------------------------|------------------|---------------|-------------------------|
| 10.0.0.0 – 10.255.255.255       | 10.0.0.0/8       | 16,777,216    | Large enterprise networks |
| 172.16.0.0 – 172.31.255.255     | 172.16.0.0/12    | 1,048,576     | Mid-size networks       |
| 192.168.0.0 – 192.168.255.255   | 192.168.0.0/16   | 65,536        | Home and small office   |

Private addresses are completely reusable — your `192.168.1.1` and your
neighbour's `192.168.1.1` coexist without conflict because they are on separate
private networks that never meet on the public internet.

### Public IP addresses

Everything outside the RFC 1918 ranges is public — globally unique, routable
on the internet, and assigned by **IANA** (Internet Assigned Numbers Authority).
Only the router needs a public address; every device behind it shares that one
public address via NAT (Network Address Translation — covered in section 4).

### How private and public addresses work together

```
Private network (RFC 1918)          │  Public internet
────────────────────────────────────│──────────────────────────
Your laptop    192.168.1.5  ─┐      │
Your phone     192.168.1.7  ─┼─► Router ◄──► Web server
Smart TV       192.168.1.9  ─┘  inside: 192.168.1.1    93.184.216.34
                               outside: 41.90.64.22
                    NAT boundary ───────────────────────
```

## 4. Special addresses

### Loopback — 127.0.0.1

Reserved to refer to the local machine itself. Traffic sent to `127.0.0.1`
never leaves the host — the OS intercepts it and loops it back internally. Used
to test whether the local network stack is functioning and to allow applications
on the same machine to communicate with each other.

Also accessible via the hostname **localhost**, which resolves to `127.0.0.1`
by default on every operating system.

```bash
ping 127.0.0.1    # tests that your own network stack is working
ping localhost     # identical result — localhost resolves to 127.0.0.1
```

The entire `127.0.0.0/8` range is reserved for loopback, but `127.0.0.1` is
the address you will always encounter.

---

### Limited broadcast — 255.255.255.255

A packet sent to `255.255.255.255` is delivered to every device on the local
network segment simultaneously. Used when a device needs to reach all devices
on the network without knowing any individual addresses.

The most common real-world example is DHCP — when a device joins a network and
has no IP address yet, it cannot address a specific server, so it broadcasts to
`255.255.255.255`. Only a DHCP server responds.

Broadcast traffic does not cross routers — it stays contained within the local
network segment.

---

### APIPA — 169.254.0.0/16

**APIPA** (Automatic Private IP Addressing) covers the range
`169.254.0.0` to `169.254.255.255`. When a device is configured to obtain an
IP address via DHCP but cannot reach a DHCP server, the OS self-assigns an
address from this range as a fallback, allowing limited local communication.

Seeing a `169.254.x.x` address on a machine is a diagnostic signal — DHCP has
failed. The machine is online but isolated from the broader network and the
internet.

```
169.254.x.x on your machine = DHCP server unreachable
```

---

### Zero address — 0.0.0.0

Used in two distinct contexts:

- **On a device:** means "this machine, unknown address" — used as the source
  address in the initial DHCP broadcast before an address has been assigned
- **In a routing table:** means "any destination" — the default route that
  catches all traffic not matching a more specific route. Written as `0.0.0.0/0`
  in routing contexts (covered in section 4)

---

### Special address summary

| Address / Range     | Name              | Meaning                                              |
|---------------------|-------------------|------------------------------------------------------|
| `127.0.0.1`         | Loopback          | This machine itself — traffic never leaves the host  |
| `255.255.255.255`   | Limited broadcast | All devices on the local network segment             |
| `169.254.0.0/16`    | APIPA             | Self-assigned fallback when DHCP is unreachable      |
| `0.0.0.0`           | Zero address      | Unknown source address or default route              |

## 5. IPv6 basics

### Why IPv6 exists

IPv4's 32-bit address space provides ~4.3 billion addresses — insufficient for
a world where every phone, laptop, TV, and smart device needs one. IPv6 uses
128 bits, providing 2¹²⁸ addresses:

```
340,282,366,920,938,463,463,374,607,431,768,211,456
(~340 undecillion — the exhaustion problem is solved permanently)
```

---

### IPv6 address structure

IPv6 is written as eight groups of four hexadecimal digits separated by colons.
Each group is 16 bits. Eight groups × 16 bits = 128 bits total.

```
2001:0db8:0000:0000:0000:0000:0000:0001
─────────────────────────────────────────
group 1          ...              group 8
(16 bits each)
```

Compare to IPv4:

```
IPv4:   32 bits  →  4 groups of  8 bits  →  decimal    (0–255)
IPv6:  128 bits  →  8 groups of 16 bits  →  hexadecimal (0000–ffff)
```

---

### Why hexadecimal

Each group is 16 bits — a maximum decimal value of 65,535. Writing eight such
groups in decimal would be unreadable. Hexadecimal is more compact: 16 bits
fits exactly into four hex digits every time.

Each hex digit represents exactly 4 bits:

```
Hex   Binary      Hex   Binary
 0    0000         8    1000
 1    0001         9    1001
 2    0010         a    1010
 3    0011         b    1011
 4    0100         c    1100
 5    0101         d    1101
 6    0110         e    1110
 7    0111         f    1111
```

Example — the group `0db8` broken down:
```
 0      d      b      8
0000   1101   1011   1000
```

At this stage you do not need to convert IPv6 addresses by hand — this table
exists so the format makes sense, not as arithmetic to practise.

---

### Address shortening rules

**Rule 1 — drop leading zeros within any group:**
```
2001:0db8:0000:0000:0000:0000:0000:0001
→   2001:db8:0:0:0:0:0:1
```
`0db8` → `db8`. `0000` → `0`. Trailing zeros within a group are kept.

**Rule 2 — replace one consecutive run of all-zero groups with `::`**
```
2001:db8:0:0:0:0:0:1
→   2001:db8::1
```
`::` can only appear once per address. If it appeared twice, you could not
determine how many zero groups each `::` represents.

**Expanding `::` back to full form:**
Count the groups shown, subtract from 8, fill the gap with that many `0000`
groups.
```
2001:db8::1  →  2 groups + 1 group = 3 shown
                8 − 3 = 5 zero groups hidden
→  2001:0db8:0000:0000:0000:0000:0000:0001
```

---

### Key IPv6 address types

| Type           | Prefix       | IPv4 equivalent   | Purpose                                           |
|----------------|--------------|-------------------|---------------------------------------------------|
| Global unicast | `2000::/3`   | Public IPv4       | Globally routable, unique on the internet         |
| Link-local     | `fe80::/10`  | APIPA `169.254.x.x` | Auto-assigned, local segment only, never routed |
| Loopback       | `::1`        | `127.0.0.1`       | This machine itself                               |
| Multicast      | `ff00::/8`   | `255.255.255.255` | One-to-many delivery to an opted-in group         |

Note: IPv6 has no broadcast. Multicast replaces it and is more efficient —
only devices that opt into a group receive the traffic, rather than all devices
on the segment.

---

### IPv4 vs IPv6 comparison

| Feature          | IPv4                  | IPv6                        |
|------------------|-----------------------|-----------------------------|
| Address length   | 32 bits               | 128 bits                    |
| Format           | Decimal, dots         | Hexadecimal, colons         |
| Total addresses  | ~4.3 billion          | ~340 undecillion            |
| Loopback         | `127.0.0.1`           | `::1`                       |
| Self-assigned    | `169.254.x.x` (APIPA) | `fe80::/10` (link-local)    |
| Broadcast        | Yes                   | No — replaced by multicast  |
| Adoption         | Dominant today        | Growing, not yet universal  |
