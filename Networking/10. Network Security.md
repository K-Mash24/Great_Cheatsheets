# Network Security Basics

Network security places a defensive layer around everything in the networking
pillar. Every concept here builds directly on protocols, addressing, and
transport mechanisms covered in earlier sections.

---

## 1. Firewalls

A firewall is a device or software that monitors and controls network traffic
based on a defined set of rules. It sits at a network boundary and decides
which traffic is permitted and which is blocked.

---

### Stateless firewall

Examines each packet in isolation with no memory of previous packets. Matches
each packet against a ruleset based on source IP, destination IP, protocol,
and port number. Fast and simple — but cannot understand the context of a
connection. A forged packet that matches the rules will be allowed through even
if it was never part of a legitimate connection.

```
Rule example:
Allow TCP from any source to 192.168.1.10 port 443
Block all other traffic
```

---

### Stateful firewall

Tracks the state of every active connection in a **state table**. Knows
whether a packet is part of an established connection, a new connection, or
unrelated traffic. A response packet is only permitted inbound if it
corresponds to an outbound connection already recorded in the state table.
Forged inbound packets that match no state table entry are dropped.

```
State table example:
192.168.1.5:51234 → 93.184.216.34:443   ESTABLISHED
192.168.1.7:51235 → 93.184.216.34:443   ESTABLISHED
```

Stateful firewalls are the standard in modern networks.

---

### Stateless vs stateful comparison

| Feature                  | Stateless                    | Stateful                          |
|--------------------------|------------------------------|-----------------------------------|
| Connection awareness     | No — each packet in isolation| Yes — tracks connection state     |
| Memory of prior packets  | No                           | Yes — state table                 |
| Protection against spoofing | Limited                   | Strong                            |
| Performance              | Faster                       | Slightly more overhead            |
| Common use               | Simple ACL filtering         | Enterprise and perimeter security |

## 2. ACLs — Access Control Lists

An ACL (Access Control List) is an ordered list of rules applied to network
traffic — typically on a router interface. Each rule specifies a condition and
an action (permit or deny). Rules are evaluated top to bottom and the first
match wins.

```
Rule 1:  Permit TCP from 192.168.1.0/24 to any port 443
Rule 2:  Permit TCP from 192.168.1.0/24 to any port 80
Rule 3:  Deny   TCP from 10.0.0.5 to any
Rule 4:  Permit IP  from any to any
```

### Implicit deny all

Every ACL has an implicit **deny all** at the end. If no rule matches a
packet, it is dropped silently. A misconfigured ACL that is too restrictive
will drop legitimate traffic without any error message — a common source of
network issues.

### ACL direction

ACLs are applied to a router interface in one of two directions:

- **Inbound** — traffic entering the interface is filtered before the router
  makes a routing decision
- **Outbound** — traffic leaving the interface is filtered after routing

## 3. Network zones and DMZ

Large networks are divided into zones — segments with different trust levels
and different security policies enforced between them.

### The three standard zones

```
Internet (untrusted)
        │
        ▼  firewall
┌───────────────┐
│      DMZ      │  ← web servers, mail servers, public DNS
│ (semi-trusted)│    publicly accessible but isolated from internal network
└───────────────┘
        │
        ▼  firewall
┌───────────────┐
│   Internal    │  ← workstations, databases, internal systems
│   (trusted)   │    never directly accessible from the internet
└───────────────┘
```

### DMZ (Demilitarised Zone)

A network segment that sits between the untrusted internet and the trusted
internal network. Servers that must be publicly accessible — web servers, mail
servers, public DNS — are placed here. If a DMZ server is compromised, the
attacker cannot directly reach the internal network because traffic between
the DMZ and the internal network is separately firewalled.

The name comes from military terminology — a buffer zone between two opposing
territories.

## 4. Common network layer attacks

### DoS (Denial of Service)

An attacker floods a target with traffic or requests, exhausting its resources
so legitimate users cannot reach it.

### DDoS (Distributed Denial of Service)

The same as DoS but the flood originates from thousands of compromised machines
(a botnet) simultaneously — making it far harder to block by source IP because
the traffic comes from many different addresses at once.

---

### SYN flood

An attacker sends a large number of TCP SYN packets but never completes the
three-way handshake. The target allocates resources for each half-open
connection until its connection table is exhausted — causing legitimate
connections to be refused.

```
Attacker:  SYN ──► target
           SYN ──► target
           SYN ──► target
           (never sends ACK — handshake never completes)

Target:    allocates resources for each half-open connection
           connection table fills up
           legitimate SYNs refused
```

Mitigation: SYN cookies — the server does not allocate resources until the
handshake is fully completed.

---

### IP spoofing

An attacker forges the source IP address of packets to disguise their origin
or impersonate another device. Often used in combination with other attacks
such as DoS amplification or to bypass IP-based access controls.

---

### Man-in-the-middle (MITM)

An attacker secretly intercepts and potentially alters traffic between two
parties who believe they are communicating directly with each other. Neither
party is aware the attacker is present. ARP spoofing is the most common layer
2 technique used to achieve MITM on local networks.

---

### ARP spoofing (ARP poisoning)

An attacker sends forged ARP replies associating their own MAC address with
the IP address of another device — poisoning the ARP caches of other machines
on the network. Traffic intended for the legitimate device is redirected to the
attacker instead. Used to enable MITM attacks or traffic interception on local
segments.

```
Legitimate:   192.168.1.1 → AA:BB:CC:DD:EE:01 (router MAC)
After attack: 192.168.1.1 → FF:FF:FF:FF:FF:FF (attacker MAC)
Result:       all traffic meant for the router goes to the attacker
```

---

### Port scanning

An attacker probes a target by sending packets to a range of port numbers to
discover which ports are open and which services are running. Used in
reconnaissance before an attack to identify exploitable services.

Common tool: **nmap** — the standard port scanning tool used in both
offensive security and legitimate network auditing.

```bash
nmap 192.168.1.1          # basic port scan
nmap -sV 192.168.1.1      # detect service versions on open ports
nmap -p 1-1024 192.168.1.1 # scan only well-known ports
```

---

### Attack summary

| Attack           | Layer    | Method                                          | Effect                                  |
|------------------|----------|-------------------------------------------------|-----------------------------------------|
| DoS              | Any      | Traffic flood from one source                   | Service unavailable                     |
| DDoS             | Any      | Traffic flood from botnet                       | Service unavailable, harder to block    |
| SYN flood        | Layer 4  | Incomplete TCP handshakes                       | Connection table exhausted              |
| IP spoofing      | Layer 3  | Forged source IP address                        | Origin disguised, access controls bypass|
| MITM             | Any      | Traffic interception between two parties        | Data exposed or altered                 |
| ARP spoofing     | Layer 2  | Forged ARP replies poison ARP caches            | Traffic redirected to attacker          |
| Port scanning    | Layer 4  | Probing port range for open services            | Reconnaissance for further attack       |

## 5. Wireshark basics

Wireshark is a packet analyser — a tool that captures live network traffic and
displays each packet in full detail at every layer of the stack. Used for
troubleshooting, protocol analysis, security auditing, and learning.

---

### Key concepts

**Promiscuous mode:** Normally a network interface processes only packets
addressed to it. In promiscuous mode it captures all packets on the network
segment — including traffic destined for other devices.

**Capture filter:** Applied before capture — limits which packets are recorded,
reducing the volume of data collected.

```
Examples:
tcp port 443           # capture only HTTPS traffic
host 192.168.1.5       # capture only traffic to/from this IP
port 53                # capture only DNS traffic
```

**Display filter:** Applied after capture — filters what is shown from an
existing capture file without discarding any data.

```
Examples:
http                        # show only HTTP packets
ip.addr == 192.168.1.5      # show packets involving this IP
tcp.flags.syn == 1          # show only SYN packets (useful for SYN flood analysis)
dns                         # show only DNS queries and responses
tcp.port == 443             # show only HTTPS traffic
arp                         # show only ARP packets
```

---

### What Wireshark shows per packet

```
Frame number and timestamp
Layer 2:  source and destination MAC addresses
Layer 3:  source and destination IP addresses
Layer 4:  protocol (TCP/UDP), source and destination port numbers
Layer 7:  application layer data where unencrypted
```

---

### Common Wireshark use cases

| Use case                    | What to look for                              |
|-----------------------------|-----------------------------------------------|
| Verify DNS resolution       | Filter: dns — check query and response        |
| Debug TCP connection issues | Filter: tcp — check SYN, SYN-ACK, ACK sequence|
| Detect ARP spoofing         | Filter: arp — look for duplicate IP mappings  |
| Inspect HTTP traffic        | Filter: http — view request and response data |
| Identify port scans         | Filter: tcp.flags.syn==1 — many SYNs, no ACKs |
| Analyse DHCP process        | Filter: bootp — see discover, offer, request, ack |
