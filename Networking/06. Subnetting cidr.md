# Subnetting and CIDR

Subnetting is the practice of dividing one large network into smaller, isolated
sub-networks. CIDR (Classless Inter-Domain Routing) is the notation system used
to express those divisions compactly. Together they form the mathematical
foundation of IP network design.

---

## 1. Core definitions

### Subnet

A logical subdivision of a larger network, created by borrowing bits from the
host portion of an IP address and reassigning them to the network portion.
Subnetting allows one large network to be divided into smaller, isolated
segments — each with its own network address, broadcast address, and usable
host range.

**Why subnet?**
- Reduces broadcast traffic — broadcasts stay within their subnet
- Isolates departments or device groups for security
- Allows different security policies per segment
- Limits the blast radius of network failures

---

### Subnet mask

A 32-bit number, written in dotted decimal format, that defines the boundary
between the network ID and the host ID in an IP address. Bits set to 1 identify
the network portion; bits set to 0 identify the host portion. All 1s always
appear before all 0s — never alternating.

```
IP address:    192.168.1.5
               11000000.10101000.00000001.00000101

Subnet mask:   255.255.255.0
               11111111.11111111.11111111.00000000
               ◄─────── network (24 bits) ────────►◄─ host (8 bits) ─►
```

---

### CIDR notation

A compact way of expressing an IP address and its subnet mask together, written
as the network address followed by a forward slash and the prefix length.

```
Instead of:   192.168.1.0  +  255.255.255.0
Write:         192.168.1.0/24
```

The prefix length is the count of consecutive 1 bits in the subnet mask.

---

### Prefix length

The number after the slash in CIDR notation, representing how many bits of the
address belong to the network ID.

```
/24  →  24 network bits,  8 host bits
/26  →  26 network bits,  6 host bits
/28  →  28 network bits,  4 host bits
/30  →  30 network bits,  2 host bits
```

---

### Block size

The total number of addresses in a subnet, calculated as 2^(host bits).
Includes the network address, all usable host addresses, and the broadcast
address.

```
Block size = 2^(32 − prefix length)
```

---

### Network address

The first address in a subnet block, where all host bits are zero. Identifies
the subnet itself and cannot be assigned to a device. Must always fall on a
multiple of the block size.

```
Example: 192.168.1.0/24
Network address: 192.168.1.0  (host bits = 00000000)
```

---

### Broadcast address

The last address in a subnet block, where all host bits are one. A packet sent
to this address is delivered to every device on the subnet simultaneously.
Cannot be assigned to a device.

```
Broadcast address = network address + block size − 1

Example: 192.168.1.0/24
Block size = 256
Broadcast address = 192.168.1.0 + 256 − 1 = 192.168.1.255
```

---

### Usable host range

The addresses between the network address and the broadcast address — the
addresses that can actually be assigned to devices.

```
First usable host = network address + 1
Last usable host  = broadcast address − 1
Total usable hosts = 2^(host bits) − 2
```

The − 2 excludes the network address and the broadcast address.

---

## 2. Subnet mask reference

| Prefix | Subnet mask       | Host bits | Block size | Usable hosts |
|--------|-------------------|-----------|------------|--------------|
| /8     | 255.0.0.0         | 24        | 16,777,216 | 16,777,214   |
| /16    | 255.255.0.0       | 16        | 65,536     | 65,534       |
| /24    | 255.255.255.0     | 8         | 256        | 254          |
| /25    | 255.255.255.128   | 7         | 128        | 126          |
| /26    | 255.255.255.192   | 6         | 64         | 62           |
| /27    | 255.255.255.224   | 5         | 32         | 30           |
| /28    | 255.255.255.240   | 4         | 16         | 14           |
| /29    | 255.255.255.248   | 3         | 8          | 6            |
| /30    | 255.255.255.252   | 2         | 4          | 2            |
| /32    | 255.255.255.255   | 0         | 1          | 0 (single host) |

/30 is the standard for point-to-point router links — exactly 2 usable hosts.
/32 refers to a single specific host — used in routing tables and firewall rules.

---

## 3. Borrowing bits

To create subnets you borrow bits from the host portion and reassign them to
the network portion. Each borrowed bit doubles the number of subnets:

```
1 bit borrowed  →  2¹ = 2  subnets
2 bits borrowed →  2² = 4  subnets
3 bits borrowed →  2³ = 8  subnets
4 bits borrowed →  2⁴ = 16 subnets
```

The number of subnets is always a power of 2. If a requirement is not a power
of 2 (e.g. 3 subnets), round up to the next power of 2 (4 subnets) and leave
the unused subnet reserved for future growth.

**New prefix length = original prefix + borrowed bits**

```
/24 + 2 borrowed bits = /26
/24 + 3 borrowed bits = /27
```

---

## 4. Subnetting by hand — the method

```
1. Determine how many bits to borrow  (2^n ≥ subnets needed)
2. Calculate the new subnet mask      (original prefix + borrowed bits)
3. Calculate the block size           (2^host bits)
4. List all subnet boundaries         (start at 0, add block size each time)
```

### Worked example — dividing 192.168.1.0/24 into 4 equal subnets

**Step 1 — bits to borrow:**
4 subnets → 2² = 4 → borrow 2 bits

**Step 2 — new subnet mask:**
/24 + 2 = /26 → 255.255.255.192

**Step 3 — block size:**
32 − 26 = 6 host bits → 2⁶ = 64

**Step 4 — subnet boundaries:**

```
Subnet   Network address    Broadcast         Usable range                  Hosts
──────────────────────────────────────────────────────────────────────────────────
1        192.168.1.0        192.168.1.63      192.168.1.1   → 192.168.1.62   62
2        192.168.1.64       192.168.1.127     192.168.1.65  → 192.168.1.126  62
3        192.168.1.128      192.168.1.191     192.168.1.129 → 192.168.1.190  62
4        192.168.1.192      192.168.1.255     192.168.1.193 → 192.168.1.254  62
```

## 5. VLSM (Variable Length Subnet Masking)

A subnetting technique that allows different subnets within the same network to
use different prefix lengths, enabling each subnet to be sized according to its
actual host requirements rather than a fixed equal size.

**Golden rule: always allocate from largest requirement to smallest.**

### Worked example — 192.168.1.0/24 with mixed requirements

```
Department    Hosts needed
──────────────────────────
Finance       50
HR            25
IT            10
Router link   2
```

**Finance — 50 hosts → /26 (62 usable)**
```
Network:    192.168.1.0/26
Broadcast:  192.168.1.63
Range:      192.168.1.1 → 192.168.1.62
Remaining:  192.168.1.64 → 192.168.1.255
```

**HR — 25 hosts → /27 (30 usable)**
```
Network:    192.168.1.64/27
Broadcast:  192.168.1.95
Range:      192.168.1.65 → 192.168.1.94
Remaining:  192.168.1.96 → 192.168.1.255
```

**IT — 10 hosts → /28 (14 usable)**
```
Network:    192.168.1.96/28
Broadcast:  192.168.1.111
Range:      192.168.1.97 → 192.168.1.110
Remaining:  192.168.1.112 → 192.168.1.255
```

**Router link — 2 hosts → /30 (2 usable)**
```
Network:    192.168.1.112/30
Broadcast:  192.168.1.115
Range:      192.168.1.113 → 192.168.1.114
Remaining:  192.168.1.116 → 192.168.1.255
```

**Summary:**

```
Subnet        Prefix  Network           Broadcast         Hosts
────────────────────────────────────────────────────────────────
Finance       /26     192.168.1.0       192.168.1.63      62
HR            /27     192.168.1.64      192.168.1.95      30
IT            /28     192.168.1.96      192.168.1.111     14
Router link   /30     192.168.1.112     192.168.1.115     2
Unused                192.168.1.116  →  192.168.1.255
```

## 6. Supernetting and route summarisation

Supernetting is the reverse of subnetting. Instead of dividing one network into
smaller pieces, you combine multiple smaller networks into one summary route
with a shorter prefix length — reducing routing table size.

Also called: **route summarisation** or **route aggregation**.

### Definitions

**Supernetting:** The process of combining multiple contiguous networks into a
single summary route with a shorter prefix length. Reduces the number of
entries in routing tables across the internet.

**Route summarisation requirements:** Three conditions must be met:
- Networks must be contiguous — no gaps in the address space between them
- The number of networks being summarised must be a power of 2
- The summary network address must fall on the correct block boundary
  (a multiple of the summary block size)

**Common bits:** The bits that are identical across all network addresses being
summarised, read from left to right. The point where they diverge determines
the summary prefix length.

### How to find the summary route — method

```
1. Write all network addresses in binary
2. Find the common bits from the left — identify where they diverge
3. Count the common bits → that is the summary prefix length
4. Summary network address = common bits + all zeros
```

### Worked example — summarising four /24 networks

```
192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
```

**Step 1 — write in binary:**
```
192.168.0.0  →  11000000.10101000.00000000.00000000
192.168.1.0  →  11000000.10101000.00000001.00000000
192.168.2.0  →  11000000.10101000.00000010.00000000
192.168.3.0  →  11000000.10101000.00000011.00000000
```

**Step 2 — find common bits:**
```
11000000.10101000.000000  00.00000000
11000000.10101000.000000  01.00000000
11000000.10101000.000000  10.00000000
11000000.10101000.000000  11.00000000
                        ▲
                   diverge at bit 23
```

**Step 3 — count common bits:**
22 bits are identical → summary prefix = /22

**Step 4 — summary network address:**
```
11000000.10101000.00000000.00000000 → 192.168.0.0
```

**Summary route: 192.168.0.0/22**

**Verification:**
```
/22 block size:  2^(32−22) = 2¹⁰ = 1024 addresses
Range:           192.168.0.0 → 192.168.3.255

192.168.0.0/24  ✓  falls within range
192.168.1.0/24  ✓  falls within range
192.168.2.0/24  ✓  falls within range
192.168.3.0/24  ✓  falls within range
```

### Supernetting vs subnetting

```
Subnetting:    /24 → /26  /26  /26  /26   (prefix gets longer,  networks get smaller)
Supernetting:  /24  /24  /24  /24 → /22   (prefix gets shorter, network gets larger)
```
