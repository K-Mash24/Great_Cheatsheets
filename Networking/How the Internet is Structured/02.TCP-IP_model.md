# TCP/IP Model

The TCP/IP (Transmission Control Protocol / Internet Protocol) model is the
practical framework that actually runs the internet. Where the OSI model is
theoretical and precise (7 layers), TCP/IP is the real-world implementation
(4 layers), collapsing layers that are rarely treated separately in practice.

---

## OSI → TCP/IP mapping

```
OSI model (7 layers)              TCP/IP model (4 layers)
─────────────────────             ──────────────────────────────────────
7 — Application   ─┐
6 — Presentation  ─┼──────────►  Layer 4 — Application
5 — Session       ─┘             (HTTP, HTTPS, DNS, SMTP, SSH, FTP,
                                  TLS/SSL, session management)

4 — Transport     ───────────►   Layer 3 — Transport
                                 (TCP, UDP)

3 — Network       ───────────►   Layer 2 — Internet
                                 (IP, ICMP)

2 — Data link     ─┬──────────►  Layer 1 — Network access
1 — Physical      ─┘             (Ethernet, Wi-Fi, ARP, NICs, cables)
```

---

## Layer definitions

### Layer 4 — Application

To provide all application-level communication between software and the
network, encompassing protocol handling for web browsing (HTTP/HTTPS), name
resolution (DNS), email (SMTP), file transfer (FTP), and remote access (SSH),
as well as encryption (TLS/SSL) and session management — absorbing the
functions of OSI layers 5, 6, and 7 into a single layer.

- In practice, modern software does not treat session management and data
  formatting as separate concerns — they are handled by the same libraries
  (browser, email client, TLS). TCP/IP reflects this by merging them.

---

### Layer 3 — Transport

To provide reliable, end-to-end delivery of data between applications using
TCP (Transmission Control Protocol), which guarantees ordered delivery and
re-transmission of lost segments, or fast connectionless delivery using UDP
(User Datagram Protocol) — mapping directly to OSI layer 4.

- This layer is unchanged from OSI. TCP and UDP are fundamental enough that
  they required no consolidation.

---

### Layer 2 — Internet

To handle logical addressing and routing of packets across interconnected
networks using IP (Internet Protocol), forwarding each packet hop-by-hop
toward its destination, with ICMP (Internet Control Message Protocol)
providing diagnostic functions such as `ping` — mapping directly to OSI
layer 3.

- Renamed from "Network" to "Internet" to reflect that this layer
  specifically handles routing across the global internet.

---

### Layer 1 — Network access

To manage the transmission of data between two devices on the same physical
network segment, handling hardware addressing via MAC addresses (Ethernet,
Wi-Fi), physical signalling (cables, radio waves), and local address
resolution via ARP (Address Resolution Protocol) — absorbing the functions
of OSI layers 1 and 2.

- TCP/IP treats the physical medium and local delivery as a single concern.
  How bits get onto the wire is outside TCP/IP's scope.

## Protocol reference

| TCP/IP layer    | OSI equivalent | Key protocols                        |
|-----------------|----------------|--------------------------------------|
| Application     | 7, 6, 5        | HTTP, HTTPS, DNS, SMTP, FTP, SSH, TLS|
| Transport       | 4              | TCP, UDP                             |
| Internet        | 3              | IP, ICMP                             |
| Network access  | 2, 1           | Ethernet, Wi-Fi, ARP, NIC, cables    |

---

## Key distinctions from OSI

- OSI is a **reference model** — used for teaching and troubleshooting
- TCP/IP is the **working model** — the actual protocol suite the internet runs on
- When documentation or exam questions reference "the network stack", they
  mean TCP/IP
- The transport and internet layers map exactly 1:1 between both models
